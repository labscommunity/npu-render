# Desktop switch design (2026-10-21)

The long-term goal is one user-facing switch that moves desktop composition to the
NPU, keeps the physical display, and restores the GPU path on demand or on any
fault. This note records what the switch can be built from after the 2026-10-21
trials, what it must add, and what stays out of scope. It is a design, not a
measurement; the trials it rests on are in
[frame-batch-live-trials-2026-10-20.md](frame-batch-live-trials-2026-10-20.md).

## What exists

Every piece of an enable/disable cycle has run on Delta as a versioned research
transaction, generated by `tools/delta/make_trial_chain.py`:

| Step | Component | Evidence |
| --- | --- | --- |
| Package | sign the UMD with the unchanged kernel binary, INF, catalog | package v37 |
| Register | stage the package, install the renderer device, qualify the worker through it, restore | registration v69 |
| Admit | install the indirect display, start the worker, grant DWM and the indirect host their leases, renew them, watch frames, restore | admission v90/v91 (36 min) |
| Recover | scheduled task (one-shot and at startup) that tears down devices, packages, processes and trace directories | every trial's `cleanup_passed` |
| Present | topology helper, frame relay, presenter, output observer: the NPU frames reach the physical panel | live v80/v81 |

Leases now renew in place (controller, worker and consumer), so an admission is
no longer bounded by one 40-minute grant; the harness's own duration limits are
lifted to four hours in generation 16.

## What the switch adds

`npu-render desktop <install|enable|disable|status>` on the Windows host:

- **install**: prepare the package for the current build if absent, stage it
  (`pnputil`), trust the lab signing certificate, and record the result. Requires
  elevation and test-signing mode, as today.
- **enable**: run registration if the package has no passing qualification, then
  start an admission with no fixed end: the bootstrap renews leases every ~30
  minutes and re-arms recovery; the presenter, relay, helper and observer run with
  the same open-ended duration. The command returns once the first NPU frame has
  reached the physical panel and leaves the admission running under its recovery
  task.
- **disable**: create the admission's `stop` file, wait for the bootstrap's own
  restoration, then run `recover.ps1` for the transaction and verify the physical
  topology, devices and packages are back.
- **status**: read the active transaction's reports (admission, bootstrap, live),
  the topology inspector and the worker's log: whether the NPU renders the desktop,
  since when, lease deadline, frame batches per minute, fallbacks, route
  disagreements, GPU 3D engine sample, last recovery.

## What must change for that

1. **Transaction naming.** Every script carries a generation number in its
   transaction identity and refuses to run twice. The identities only have to match
   `^[a-z0-9-]+$` (topology helper) and `^[a-zA-Z0-9_.-]+$` (file names), which the
   generator's numbered names already do, so the switch owns the counter: it reads
   the highest admission generation present on the host, calls the generator with
   the next number and `--registration-generation` of the package's last passing
   registration, and runs the emitted scripts. No new naming scheme is needed.
2. **Open-ended admission.** The bootstrap's monitor loop ends at
   `--monitor-seconds`; the switch passes a large value (four hours is the lifted
   harness limit) and stops it early through the `stop` file. Lifting the four-hour
   limits again is mechanical (the same six components).
3. **No trial stimulus.** The live wrapper injects input, animation and a
   known-colour fixture to measure the trial. `enable` runs the admission,
   topology helper, relay, presenter and observer only; the stimulus, repeated
   input and analysis stay in the trial path.
4. **Preconditions become status, not asserts.** The scripts throw on dozens of
   prerequisites (prior transactions passed, no other experiment active, memory
   integrity running). The switch checks the same facts and reports which one
   blocks, instead of a stack trace.
5. **Recovery at startup.** The recovery task's startup trigger already restores
   after a reboot; `status` must report that this happened.

## Out of scope

Ordinary application admission (browser, video, 3D), Tahoma benefit measurement
and the per-flush latency that holds the desktop at 2.4 updates/s are separate
gates; the switch makes the current renderer usable and safe to leave running,
it does not change what it renders or how fast.

## State on 2026-10-21 evening

numbered chain, uploads it and launches the admission as a detached sequence;

## Ordinary applications while the switch is on (2026-10-21 night)

With the indirect display primary, the system's default adapter is ours, and an
ordinary application's `D3D11CreateDevice(nullptr, HARDWARE, ...)` reaches
`OpenAdapter10` in our driver. Without a lease that returns
`DXGI_ERROR_UNSUPPORTED`: the adapter probe the live wrapper starts recorded
`887a0004` for both device requests in every stimulus-free run so far, so an
application on the enabled desktop could not create a hardware device. That is a
loss against the GPU path (priority 2) and the open half of gate 6.

The admission mechanism already existed in one-shot form: the interactive broker
(`nr_auto_interactive_broker`) publishes the admission for the console session
(`Global\T8.NpuRender.AutoAdmission.v2.<session>`, a 120 s window), the driver's
`read_or_request` finds the publication when a process has no lease, verifies the
broker and worker identities, requests over the broker's pipe, and the broker
verifies the pipe client's identity, SID, session and nonce before writing that
process a scope-3 lease mapping. The registration qualification exercises this
with one cued consumer; the broker then exits.

The switch needs the same for every client for as long as the admission lasts:

- Broker v8 `--serve <stop file>` keeps one publication for the session and
  admits clients in turn (one pipe instance, the driver waits on a busy one),
  refreshing the publication window and renewing every live client's lease in
  place every 40 s (scope-3 grants are 120 s at most; the driver's `Admission`
  re-reads a renewal within its margin), pruning clients that exited, until the
  stop file appears or the worker ends. Each admission, rejection and renewal
  round is one JSON row.
- The stimulus-free bootstrap starts it right after the compositor and indirect
  host leases (`native_resident_broker_v1.py`), grants the console user query
  access to the worker and broker processes and tokens so clients can verify
  both peers, folds the broker's counts into the admission report, and closes
  it before the grants are restored.
- Driver tree v46 binds an interactive client to its own thread desktop
  (`own_desktop_is_default`) instead of the input desktop, so an admitted
  application keeps rendering through a screen saver or lock screen the same
  way the compositor does since build v44; and `request()` waits on a busy
  broker pipe instead of failing the device.

What this does not do: the application's draws run on the same NPU worker as
the compositor's, at the same speed, and an application that needs the iGPU
(the Tahoma case) must select it explicitly, as it can today through DXGI. The
evidence for gate 6 is the wrapper's `application_default_device_created`, the
broker's rows, and the lease-holding consumer (`--hold`) proving renewal across
the 120 s grant, recorded in the trials report once run.

## When the worker ends (2026-10-22 night)

The native driver cannot render on the host: the CPU executors are compiled out
of the probe build (`#ifndef NR_NATIVE_PROBE`), and a WARP-like in-process
fallback for frame batches would need a host implementation of the per-draw
routes as well as the kernel. So a lost worker is handled by replacement, not
by degradation:

- The driver's exchange (`IndexedNpuExchange::send`) treats a failed request as
  the start of a failover: it re-reads the admission (`read_or_request`) every
  250 ms for up to 15 s, binds to the worker it names once that worker is alive,
  and sends the request once more. Only the retry's failure poisons the device
  the way any failure did before. DWM's render thread stalls for the failover
  instead of losing its device.
- The generated bootstrap polls the worker; when it has ended, `WorkerFailover`
  starts a replacement on the same private pipe (appending to the same logs,
  with its own capture and provider directories), grants the compositor and
  indirect host query access to it, waits for its ready row, rewrites every
  lease with the new worker's identity and fresh ticks, and restarts the
  resident broker. A rewrite is not a renewal, so a consumer's cached admission
  is replaced rather than extended, which is what binding to a new worker
  needs. Three replacements per admission; the fourth loss ends it as before.
- Automatically admitted clients lose their lease mappings with the broker and
  re-request from the new publication inside the same failover window.

Built as tree v48 (clean, lease contract passing). The probe is an admission
whose worker is stopped by a scheduled task mid-run with a lease-holding client
spanning the stop: the expected evidence is one `worker_restarts` record,
`exchange_failover` rows in the compositor's driver trace, frames continuing
after the restart, and the client still admitted. Not run yet.
