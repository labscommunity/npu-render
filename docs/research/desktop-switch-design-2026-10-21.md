# Desktop switch design (2026-10-21)

The long-term goal is one user-facing switch that moves desktop composition to the
NPU, keeps the physical display, and restores the GPU path on demand or on any
fault. This note records what the switch can be built from after the 2026-10-21
trials, what it must add, and what stays out of scope. It is a design, not a
measurement; the trials it rests on are in
[frame-batch-live-trials-2026-10-20.md](frame-batch-live-trials-2026-10-20.md).

## What exists

Every piece of an enable/disable cycle has run on Delta as a versioned research
transaction, generated by `tools/delta/make_trial_chain.py`:

| Step | Component | Evidence |
| --- | --- | --- |
| Package | sign the UMD with the unchanged kernel binary, INF, catalog | package v37 |
| Register | stage the package, install the renderer device, qualify the worker through it, restore | registration v69 |
| Admit | install the indirect display, start the worker, grant DWM and the indirect host their leases, renew them, watch frames, restore | admission v90/v91 (36 min) |
| Recover | scheduled task (one-shot and at startup) that tears down devices, packages, processes and trace directories | every trial's `cleanup_passed` |
| Present | topology helper, frame relay, presenter, output observer: the NPU frames reach the physical panel | live v80/v81 |

Leases now renew in place (controller, worker and consumer), so an admission is
no longer bounded by one 40-minute grant; the harness's own duration limits are
lifted to four hours in generation 16.

## What the switch adds

`npu-render desktop <install|enable|disable|status>` on the Windows host:

- **install**: prepare the package for the current build if absent, stage it
  (`pnputil`), trust the lab signing certificate, and record the result. Requires
  elevation and test-signing mode, as today.
- **enable**: run registration if the package has no passing qualification, then
  start an admission with no fixed end: the bootstrap renews leases every ~30
  minutes and re-arms recovery; the presenter, relay, helper and observer run with
  the same open-ended duration. The command returns once the first NPU frame has
  reached the physical panel and leaves the admission running under its recovery
  task.
- **disable**: create the admission's `stop` file, wait for the bootstrap's own
  restoration, then run `recover.ps1` for the transaction and verify the physical
  topology, devices and packages are back.
- **status**: read the active transaction's reports (admission, bootstrap, live),
  the topology inspector and the worker's log: whether the NPU renders the desktop,
  since when, lease deadline, frame batches per minute, fallbacks, route
  disagreements, GPU 3D engine sample, last recovery.

## What must change for that

1. **Transaction naming.** Every script carries a generation number in its
   transaction identity and refuses to run twice. The identities only have to match
   `^[a-z0-9-]+$` (topology helper) and `^[a-zA-Z0-9_.-]+$` (file names), which the
   generator's numbered names already do, so the switch owns the counter: it reads
   the highest admission generation present on the host, calls the generator with
   the next number and `--registration-generation` of the package's last passing
   registration, and runs the emitted scripts. No new naming scheme is needed.
2. **Open-ended admission.** The bootstrap's monitor loop ends at
   `--monitor-seconds`; the switch passes a large value (four hours is the lifted
   harness limit) and stops it early through the `stop` file. Lifting the four-hour
   limits again is mechanical (the same six components).
3. **No trial stimulus.** The live wrapper injects input, animation and a
   known-colour fixture to measure the trial. `enable` runs the admission,
   topology helper, relay, presenter and observer only; the stimulus, repeated
   input and analysis stay in the trial path.
4. **Preconditions become status, not asserts.** The scripts throw on dozens of
   prerequisites (prior transactions passed, no other experiment active, memory
   integrity running). The switch checks the same facts and reports which one
   blocks, instead of a stack trace.
5. **Recovery at startup.** The recovery task's startup trigger already restores
   after a reboot; `status` must report that this happened.

## Out of scope

Ordinary application admission (browser, video, 3D), Tahoma benefit measurement
and the per-flush latency that holds the desktop at 2.4 updates/s are separate
gates; the switch makes the current renderer usable and safe to leave running,
it does not change what it renders or how fast.
